因此低并发 C4 的主要收益来自 CodePin 源码路径；达到原 S8 容量附近后，源码优化不再提高吞吐，候选 vLLM 组合才消除排队并恢复 P95。这与 P4/C16 的原生服务指标一致：组合配置的平均请求排队由 189.677 ms 降至 0.021 ms，但单请求 prefill、decode 和 TPOT 均没有变快。这里的“vLLM 增量”包含 S8→S64、扩大 CUDA Graph 捕获、FI 全注意力后端及其交互，尚未用最终后端选择拆成互斥贡献。

V100 的调参 C4/C8/C16、冷前缀 C4 和验证 C16 均三轮通过。验证 C8 在第二、三轮出现 python-pptx 的失败轨迹，该任务的有效率为 98.32%/98.87%，低于冻结基线 99.39%，V86 和 V102 均拒绝。原基线有过相同的 8 轮、6 个工具错误、435 个生成 token 的失败统计特征，但没有保存逐 token 轨迹，不能据此认定根因相同；本轮失败频率更高，不能判为无退化。失败任务、18 个结果目录和三次回放均保留，没有改变门槛。
